# MCP-сервер ImageCare

Экспериментальный встроенный MCP-сервер (Model Context Protocol) для сценария отбора фотографий
с флешки. Сервер живёт внутри процесса ImageCare, поэтому инструменты работают с теми же живыми
сервисами и тем же окном, что и пользователь: агент видит текущую папку, аннотации и сессии
отбора, а не отдельную копию состояния.

## Как включить

1. Откройте **Настройки → MCP-сервер**.
2. Включите переключатель и при необходимости поменяйте порт (по умолчанию `5277`).
3. Статус рядом с переключателем показывает адрес, например `http://127.0.0.1:5277/mcp`,
   либо текст ошибки, если порт занят.

Те же значения можно задать в `%LOCALAPPDATA%\ImageCare\configuration.json`:

```json
{
  "McpServerEnabled": true,
  "McpServerPort": 5277,
  "McpServerAccessToken": null
}
```

Данные сессий отбора и кеши лежат в `%LOCALAPPDATA%\ImageCare\Mcp`.

## Подключение клиента

Транспорт — стандартный **Streamable HTTP**, поэтому подойдёт любой MCP-клиент с поддержкой
HTTP-серверов (Claude Desktop, Claude Code, Cursor, JetBrains, SDK-клиенты и т. д.).

```json
{
  "mcpServers": {
    "imagecare": {
      "type": "http",
      "url": "http://127.0.0.1:5277/mcp"
    }
  }
}
```

Если задан `McpServerAccessToken`, добавьте заголовок:

```json
{
  "mcpServers": {
    "imagecare": {
      "type": "http",
      "url": "http://127.0.0.1:5277/mcp",
      "headers": { "Authorization": "Bearer <токен>" }
    }
  }
}
```

Проверка доступности без авторизации: `GET http://127.0.0.1:5277/health`.

## Инструменты

| Инструмент | Назначение |
| --- | --- |
| `imagecare_server_info` | Версия, корни поиска, закреплённые теги, доступность UI. |
| `imagecare_list_drives` | Диски, включая карты и флешки: тип, готовность, свободное место. |
| `imagecare_list_folders` | Подпапки и количество медиафайлов в них. |
| `imagecare_media_metadata` | Размер, время съёмки, рейтинг, теги, EXIF. |
| `imagecare_media_previews` | Уменьшенные JPEG-превью как MCP image-блоки (для мультимодальных моделей). |
| `imagecare_rating_set` | Изменить рейтинг (0–5 звёзд) у файлов, сохраняя теги; по умолчанию `dryRun=true`. |
| `imagecare_session_create` | Начать/продолжить сессию отбора; файлы сортируются по времени съёмки и группируются в серии кадров. |
| `imagecare_session_get` | Текущая партия, при `includePreviews=true` — с картинками. |
| `imagecare_session_sync` | Прочитать решения пользователя: кто оставлен, кто не определён, кто уже удалён. |
| `imagecare_session_next` | Перейти к следующей партии. |
| `imagecare_session_stats` | Сводная статистика по партиям и по всей сессии. |
| `imagecare_session_delete_remaining` | Удалить только «неопределённые» файлы; по умолчанию `dryRun=true`. |
| `imagecare_tags_all` | Все теги в индексе аннотаций. |
| `imagecare_search` | Поиск по рейтингу, тегам и пути. |
| `imagecare_tags_suggest` | Подсказки тегов на основе того, что пользователь уже оставил рядом, тегов папки и закреплённых тегов. |
| `imagecare_tags_apply` | Добавить теги к файлам (с предварительным `dryRun`). |
| `imagecare_folder_tags_get` | Теги папки с учётом наследования `folder-tags.txt` (все предки, ближний первым). |
| `imagecare_folder_tags_set` | Добавить теги в `folder-tags.txt` (UTF-8 с BOM, без дублей). |
| `imagecare_folder_tags_propose` | Предложить папке новые теги на основе её содержимого. |
| `imagecare_ui_state` | Что сейчас открыто: панели и папки, выбранный файл (`focusedFilePath`) и видимые карточки ленты (`visibleFiles` с рейтингом и тегами). |
| `imagecare_open_folder` | Открыть папку в левой или правой панели: папка выделяется в дереве, раскрываются предки, лента прокручивается к ней. |

Все изменяющие операции (`imagecare_session_delete_remaining`, `imagecare_tags_apply`,
`imagecare_rating_set`, `imagecare_folder_tags_set`) поддерживают `dryRun` и по умолчанию сначала
показывают план. Удаление
ограничено `MaxFilesPerDelete` (200 файлов за вызов), обойти лимит можно только явным
`allowBulk=true`.

### UI-мост

`imagecare_ui_state` отдаёт снимок живого окна: открытые папки обеих панелей, панель с последним
выбранным кадром (`selectedPanel`), путь выбранного файла (`focusedFilePath`) и карточки, реально
видимые в ленте (`visibleFiles` — путь, имя, рейтинг, теги). Если кадр ещё не выбран, `visibleFiles`
показывает ленту панели, с которой работали последней (пользователь или ассистент через
`imagecare_open_folder`).

`imagecare_open_folder` не только переключает панель, но и выделяет папку в дереве: раскрывает
предков и прокручивает к выбранному узлу. Если папка находится вне загруженного дерева (например,
ещё не подключённый съёмный диск), панель всё равно переключится, но без выделения в дереве.

## Сценарий отбора

1. Пользователь вставляет флешку, агент вызывает `imagecare_list_drives` и `imagecare_list_folders`.
2. `imagecare_session_create` разбивает папку на партии по ~50 файлов, не разрывая серии кадров
   (кластеризация по времени съёмки).
3. `imagecare_session_get(includePreviews=true)` — агент показывает/обсуждает кадры и предлагает теги
   (`imagecare_tags_suggest`), но **не решает за пользователя**.
4. Пользователь сам ставит рейтинг, теги и переносит кадры в библиотеку. Если пользователь прямо
   просит, агент может изменить рейтинг через `imagecare_rating_set` (сначала `dryRun`).
5. `imagecare_session_sync` — агент читает решения. «Оставлен» = файл на месте и есть рейтинг
   `>= KeepRating` (по умолчанию 1) или хотя бы один тег.
6. По явной команде «удаляй остальное» — `imagecare_session_delete_remaining` сначала `dryRun`,
   затем реальное удаление только неопределённых файлов.
7. `imagecare_session_next` — следующая партия, `imagecare_session_stats` — статистика.

## Безопасность

- Сервер слушает только loopback (`127.0.0.1`/`localhost`/`[::1]`), заголовок `Host` проверяется —
  это защищает от DNS-rebinding.
- Доступ к файлам ограничен `MediaSearchRootPaths`, съёмными дисками и корнями текущих сессий;
  относительные пути и выход за пределы корня отклоняются.
- Необязательный bearer-токен защищает все маршруты, кроме `/health` (сравнение постоянного времени).
- Удаление выполняется только для неопределённых файлов, с лимитом и предварительным планом.

## Ограничения

- Приложение теперь требует разделяемый фреймворк **ASP.NET Core Runtime** (из-за встроенного
  Kestrel). При публикации учитывайте это или собирайте self-contained.
- Сервер работает в режиме `Stateless`: нет серверных уведомлений и подписок, каждый запрос
  самостоятелен.
- Превью уменьшаются до 1024 px по длинной стороне (настраивается аргументом `maxEdge`) и
  кешируются; полноразмерные файлы наружу не отдаются.
- `imagecare_search` и `imagecare_tags_all` работают по индексу аннотаций (тому, что пользователь
  уже отмечал), а не по всему диску.
